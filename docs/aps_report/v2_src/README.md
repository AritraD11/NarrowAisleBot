# How the restructured report was built

`../APS Report Aritra - restructured.docx` is the September document regrouped
around the three strands rather than around the sections of a methods-and-results
paper. The prose that already existed is copied out of the previous file run for
run rather than retyped, so nothing that has already been read changes by
accident; the new material is in `content.py` in quotes, and everything else is a
paragraph index into the old document.

```
content.py      the figure plan, the abstract, and the body as a list of
                elements: new prose, reused paragraphs, figures, tables, equations
build_v2.py     turns that list into the .docx, and refuses to write if a check fails
_tables_eqs.py  the four tables and four native Word equations, lifted unchanged
                from final_src/build_report.py
qa.py           the checks, run against the written file rather than the source
pages.json      the real page of every heading, measured off a rendering
headings.json   every heading in document order, written by the build
```

Build:

```
NAB_BASE=<the September .docx> NAB_MEDIA=<its unzipped word/media> \
    python3 build_v2.py
```

The old Chapters 5 and 6 are Chapter 1's sections 1.3 to 1.16, in the same order
and with the same content, so every cross-reference in the reused prose had to
move. Each move is a `(find, replace)` pair in `build_v2.py`, the number of times
each one fired is printed, and the build asserts that no reference to the old
numbering survives anywhere in the finished document.

## What is new rather than moved

Section 1.6 is the only substantial new body text: the velocity loop, and where
each gain came from, written against `aislebot_esp32.ino` rather than against any
earlier description of it. It states plainly that the proportional gain was
derived from an assumed plant time constant of 0.18 s, that the measured constant
turned out to be about 0.09 s, and that the gain was kept anyway because two
recomputed values were tested against it across sixteen setpoint-and-motor
combinations and both overshot more.

Chapters 2 and 3 gain their own motivation, literature, method and conclusion
sections. The Introduction and Chapter 4 are new throughout.

## Three diagrams were checked against the firmware before being redrawn

Three rendered diagrams were supplied for inclusion. Two carried errors and are
corrected here.

**The velocity loop.** The feedforward was written with its two coefficients on
the wrong terms and the velocity symbol mangled, so the static gain multiplied
the velocity and the viscous gain multiplied its sign. The firmware's model is
`Kff·ω + Kstat·sgn(ω)`. The loop rate was also missing; it is 100 Hz.

**The monitoring architecture.** It showed the MQTT broker receiving Wi-Fi, LoRa
and SMS. Nothing supports that. The long-range radio is read from its gateway by
a dedicated service that writes straight to the database, and the cellular
channel delivers a message to a person and is never ingested at all. Both are
corrected, and the radio parameters from `figure_src/f_iot.py` are added.

**The deployed electronics.** It showed `PID @ 50 Hz · Kp50 Ki30 Kd3`. Those are
the bench-calibration sketch's defaults (`firmware/nab_bench_calibration_esp32.ino`),
not the deployed firmware's, which is 100 Hz with Kp 45, Ki 250, Kd 0.5. Its
title band was also overprinted. That version was placed into the September
document as image4; Figure 5 here uses the repository's own
`docs/hardware/nab_circuit_diagram.png`, which is already correct on both
counts. The supplied version's pin map and encoder channel map were checked
against `aislebot_esp32.ino` and are right.

**A fourth correction, found later.** Once the monitoring project's own report
was available, the earlier architecture figure turned out to be wrong in two
further ways and a fifth claim turned out to be stale. The cellular channel is
bidirectional, not outbound: the node accepts the same command vocabulary on
every channel including short messages. There are two dashboard control
endpoints, not one, selected at runtime by a dashboard variable. And the claim
that the fan tachometer never divides by its sample window, which appears in an
earlier audit figure, was checked against the source and is incorrect; the
residual error is a small high bias from loop latency. Figures 17 and 18 are
drawn from the verified register rather than from the earlier summary.

## The contents

The page numbers are measured, not typed. The build writes the document, a
rendering of it is read back and the page of every heading found by its face
rather than by its words (the contents repeats every heading verbatim, so a text
match finds the contents instead), and the build runs again with those numbers.
`qa.py` then checks each printed number against the render, and the render is
confirmed to be a fixpoint: adding the numbers does not move anything.

Carlito and Caladea are installed for the rendering, so LibreOffice substitutes
metric-compatible faces for Calibri and Cambria rather than DejaVu. With Times
New Roman already metric-compatible with Liberation Serif, the render is close to
what Word will produce, though not guaranteed identical.

## What `qa.py` checks

1. Figure captions run 1 to 20 with no gap and no repeat.
2. Every `Figure N` in the prose points at a caption that exists, and every
   figure is referred to at least once outside its own caption.
3. Every `Section N.M` and `Chapter N` in the prose points at a heading that exists.
4. No reference to the old numbering survives.
5. No banned wording and no em dash.
6. Every placed picture, with the density it is placed at.
7. Every page number in the contents against the render.

## Picture density

Every placed picture sits between 280 and 694 dpi except two, and both have the
same cause:

- **The institute crest**, 150 dpi. No larger copy exists anywhere.
- **Figure 11**, endpoint closure, 199 dpi. The figure exists nowhere in the
  repository, only inside the September document.

The generated figures render at 260 dpi against their own canvas, which lands
between 420 and 540 dpi once placed at full text width. The appliance and
dashboard photographs, which were the two softest pictures in the previous
draft, now come out of the monitoring project's own report at their native size
and are placed inside composite plates, which took them from 115 and 192 dpi to
426.

Advanced, Image Size and Quality: select this document, tick "Do not compress
images in file", set default resolution to High fidelity. Export with "Optimize
for: Standard".
